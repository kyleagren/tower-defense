# Controls & UI

Keyboard and mouse and a controller are both first-class; tested on a PS4 pad. Every input goes through a named Input Map action carrying both bindings, so nothing in gameplay code names a key or button. `InputDevice` tracks whichever kind of device the player touched last (small stick drift and mouse bumps don't count), and the rest adapts to it: button prompts, the cursor, and whether the left stick drives the character or an open menu.

**Controller layout (field):**

| Input                                   | Action                                                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Left stick / Right stick                | Move / look (squared response curve, `StickLookSpeedDegrees` at full tilt)                                    |
| L3                                      | Sprint                                                                                                        |
| R2 / L2                                 | Attack and confirm placement / alt action (aim, block) and cancel placement                                   |
| Cross                                   | Jump                                                                                                          |
| Circle                                  | Dodge; cancel (`ui_cancel`) — backs out of token pick mode, a placement, or an ability waiting for its target |
| Square                                  | Interact / pick up                                                                                            |
| L1 + Cross / Circle / Square / Triangle | Abilities 1–4                                                                                                 |
| Hold R1 + d-pad left / up / right       | Tokens 1–3 — author in Build and the hub, deploy in Combat                                                    |
| D-pad up / down (hold)                  | Repair / destroy the Ritual in view                                                                           |
| D-pad right                             | Ready up                                                                                                      |
| Triangle                                | Build menu (Build and the hub)                                                                                |
| Touchpad / Share / Options              | Inventory / character sheet / pause                                                                           |

- **Chords live in code, not the Input Map**, which can't require two buttons at once. `InputChords` gates them: while L1 is held the face buttons cast abilities and jump, dodge, interact and cancel stand aside; while R1 is held, repair, destroy and ready stand aside, since the d-pad belongs to tokens. A keyboard never holds a modifier, so its presses always pass straight through. Unmodified d-pad left is kept free for later (map pings and the like).
- **Holding R1 _is_ pick mode** on a controller in Combat — pressing it enters, releasing exits — where the keyboard's `Q` toggles. In Build and the hub, `Q` opens the build menu instead.
- **Menus:** Cross confirms, Circle backs out, the left stick or d-pad moves focus, and a held direction repeats after 0.3s, every 0.1s (`UiNavigationRepeat` — nothing repeats controller input on its own). Wherever a layout is too sparse for Godot's automatic nearest-control pick, focus neighbors are set explicitly: the inventory's paper doll and the edge between the inventory and a crafting or vendor panel beside it. **On a controller, movement stops while any panel is open**, since the left stick is navigating it; keyboard players keep walking. Two exceptions: the Level and Sentinel pickers and the build menu stand the character still on any device; and a station's panel (crafting, vendor, stash) closes like Escape once its user walks more than `GameRules.StationLeaveReach` (5m) from it.
- **Mouse:** captured during play, released while any panel is open — and hidden instead on a controller, where a cursor parked wherever the mouse was left is only clutter. Escape never releases the mouse on its own.
- **Button prompts** name the binding for the current device (`InputPromptHelper`) and update the moment the player switches. A controller reads as PlayStation or Xbox from its reported name — a Switch pad reads as Xbox for now. The PlayStation face shapes and d-pad arrows are drawn (`ButtonGlyph`) rather than typed, since font coverage of those symbols varies. The field HUD's token and ability rows carry a modifier chip at their left (R1 or `Q` for tokens, L1 for abilities, controller only); on a controller both rows show their slot badges all the time, while on keyboard only one row does, since they share `1`/`2`/`3`.
- **Hint bar (`HintBar`, `ui/hints/`)** — a strip naming the controls a new player wouldn't guess.
  - **Where it sits.** Its hints come from the panel on top of `UiPanelStack`, but it sits along the bottom edge of whichever open panel the pointer (focus on a controller, the cursor on a mouse) is in — a station and Inventory sit side by side, so it follows the side being worked in. Pointing at nothing, it stays under the last panel pointed into while that's still open, and otherwise goes under the top one (the bottom of the screen, for a full-screen panel). A panel whose content reaches its bottom edge leaves `HintBar.ReservedHeight` free for it.
  - **Sources.** A panel opts in by implementing `IHintSource`, adding its current hints to a list most-important first. The bar asks every frame and rebuilds only when the list or the device changes, so hints follow the panel's state — a carried item, a filled socket — without any panel signalling changes.
  - **One row only:** entries that don't fit the panel's width drop off the end, so a panel keeps its list short by offering only what applies to what's focused.
  - **Each entry** is the binding as a pill (PlayStation shapes drawn, as `PromptBadge` does), a **HOLD** tag for hold actions, and a label; `Hint.MouseText` stands in for inputs the action doesn't carry, like a click or the build menu's hardcoded right-click.
  - **It lives in `main.tscn`** above every menu layer (layer 11, processing while paused); split-screen would move it into each HUD.
  - **Never hint confirm or back** — everyone knows them; the bar is for the non-obvious. The plain menus (pause, options, main menu, character sheet, level and Sentinel select) therefore have no hints at all.
  - **Built:** the inventory — Learn on a rune tome, otherwise Equip/Unequip where it fits, hold Details, hold Compare (not on an equipped item); with an item carried, only Put Back / hold Drop on a controller, or Click Outside to drop on a mouse.
  - **Built:** the stash, vendor and crafting table (`StationHints`). The station is the top panel, so it speaks for both sides. On an Inventory item: Quick Move first, labelled by where it goes (To Stash if the tab has room, Sell, To Crafting if the slot is empty), then Inventory's own hints. On a station item: To Inventory for a slot (stash cell, crafting slot) when Inventory has room — a vendor row is bought with confirm, so it gets none — then Details and Compare. On a controller, L1 names the station from Inventory and R1 names Inventory from the station. Carrying an item over the vendor with a mouse reads Click: Sell instead of Drop. Each station panel needs `HintBar.ReservedHeight` clear at its bottom, as Inventory has.
  - **Built:** the build menu — on the inscription, HOLD Tiers on a filled socket and HOLD Name It on Save Favorite; Tokens on every screen but the token wheel (R1, or the three token keys on keyboard); Close (`Q` / Triangle) from any screen. Nothing while a favorite is being named.
  - **Built:** Organize — only mid-action: Move and Back: Put Back with an entry picked up, Back: Cancel with a pin slot held or a favorite being pinned. Nothing while renaming.
  - **Not built yet:** field states that aren't panels — placement and token pick mode — plus "Hold Alt / R3 to Inspect" on the Ritual look prompt, joined there by Edit and Copy once they exist.
- **Movement.** Every character (`PlayerCharacter`) has a double jump: `AirJumps` (1) mid-air jumps, refilled on landing and still there after walking off a ledge, blocked by everything that blocks a ground jump. `StepHeight` (0.35m) lets a character walk up a ledge that short instead of stopping dead — `CharacterBody3D` only climbs slopes, so `StepClimber` checks before each move whether lifting the body would clear what it's walking into and land it on walkable floor, and lifts it if so. The lift is instant, so the camera hops a step rather than gliding.

**Pause menu** — Options, or Escape when nothing else wanted it: Resume / Options / Return to Hub (in a match only — a forfeit, carried out by the level's `GameOverHandler`) / Exit Game. Opening it closes any other open panel first. It freezes the game unless `PlayerProfiles.IsMultiplayer` — menus are per player, so in co-op, split-screen included, each player opens their own without stopping anyone else's game, which is also why it lives in the HUD rather than an autoload.

**Options** holds the display toggles ([hub_and_tools.md](hub_and_tools.md)), saved per machine.

**Rebinding (designed, not built).** A Controls screen in Options with two tabs, **Keyboard & Mouse** and **Controller**, each a list of actions and their current binding. Selecting a row waits for the next press to become its binding (Escape backs out); each row resets on its own, and there's a Reset All. One binding per action per device for now; a keyboard secondary is the likely first addition.

- **It's an Input Map edit.** Gameplay only names actions, so rebinding swaps an action's events at runtime (`InputMap.ActionEraseEvents`/`ActionAddEvent`), and everything that reads the action follows — including every button prompt, badge and hint, which `InputPromptHelper` already reads off the live Input Map. Chords follow too, since `InputChords` checks the `ability_modifier`/`token_modifier` actions.
- **Saved per machine** with `ConfigFile` (`user://controls.cfg`), beside `settings.cfg` and `video.cfg`, holding only what the player changed and applied at startup before anything reads input — so an action added later keeps its default. Keyed by device, so split-screen can make it per seat later.
- **Conflicts are checked within a context, not globally.** Some keys are shared on purpose — 1/2/3 are abilities and tokens, `Q` is the build menu and token mode, `E` is interact and pick up, Shift is sprint, compare and quick-equip — so actions are grouped by when they're live (field, menus, inventory), and only a clash inside one group asks to swap.
- **Not rebindable:** menu navigation, confirm and back (`ui_*`), and mouse and stick look, which are sensitivity settings rather than bindings. The build menu's right-click back is hardcoded in `BuildMenu` today and becomes an action first.
- **Controller gotcha:** the press that started listening must not be taken as the new binding.
- Follows the pattern of Godot's input-remapping demo rather than inventing one.

**Not built:** stick sensitivity and invert settings, aim assist, rumble, button-icon art, the affix detail popup on a controller, and an on-screen keyboard (Steam's or a console's) for naming favorites. **Local split-screen** would need each controller assigned to a player seat — today every binding and `InputDevice` treat all devices as one player.
